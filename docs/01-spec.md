# Документация: Сервис бэктестинга стратегий (SMC + Footprint) v3

## 1. Общее описание

Данный сервис представляет собой профессиональный полуавтоматический аналитический терминал для бэктестинга торговых стратегий. Он объединяет макро-анализ по концепции **Smart Money (SMC)** и микро-анализ сведения ордеров (**Footprint**).

В 3-й версии сервис получил полноэкранный интерфейс в стиле TradingView. Больше нет разделённых экранов или громоздких боковых панелей. Всё пространство отдано графику, а инструменты управления реализованы в виде удобных плавающих виджетов.

**Главная парадигма работы:**

> Макро-контекст ➔ Автоматический сканер ➔ Микро-зум по клику.

## 2. Рабочий процесс (Workflow) и Таймфреймы

Сервис работает в режиме одного экрана с бесшовным переключением между двумя таймфреймами:

1. **Разметка на HTF (15m)** — пользователь загружает историю и анализирует структуру рынка на 15-минутном графике. С помощью плавающего меню слева он включает инструмент «Разметка» и выделяет прямоугольниками зоны интереса (POI, Order Blocks, FVG).
2. **Сканирование** — пользователь нажимает кнопку «Поиск входов». Скрипт в фоне проверяет 5-минутные кластера внутри выделенных зон. Если алгоритм находит идеальный сетап, зона на графике HTF автоматически загорается зелёным цветом, а в левом нижнем углу появляется отчёт со статистикой.
3. **Детальный анализ на LTF (5m)** — пользователь кликает по подсвеченной зелёной зоне прямо на графике. Появляется контекстное меню с предложением перейти на LTF. При нажатии график переключается на 5-минутный таймфрейм и автоматически масштабируется ровно под выбранную зону, сразу отображая Footprint и точку входа.
4. **Возврат** — нажав кнопку «Назад к HTF» в верхней панели, пользователь возвращается к общему обзору структуры.

## 3. Инструменты интерфейса (UI/UX)

### Плавающий Toolbox (слева сверху)

| Иконка | Режим | Описание |
|---|---|---|
| 🖱️ | **Навигация** | Режим просмотра. Перемещение графика зажатием левой кнопки мыши. |
| ✋ | **Разметка POI** | Режим рисования. Зажатие мыши создаёт прямоугольную зону. **Доступно только на HTF.** |
| 🔍 | **Поиск** | Запуск сканера по всем нарисованным зонам. |
| 🗑️ | **Очистка** | Удаление всех зон и сигналов. |

### Панель навигации графика (в шапке графика)

Кнопки точного сдвига (Влево/Вправо) и масштабирования (Приблизить/Отдалить). Альтернатива — скролл колесиком мыши.

### Перекрестие (Crosshair)

Автоматически следует за мышью, помогая точно определять ценовые и временные уровни.

### Плавающий отчёт (слева снизу)

Виджет, отображающий количество размеченных зон, количество зон с успешными сигналами и общее число найденных входов.

## 4. Визуализация кластеров (Footprint)

При переходе на LTF и достаточном приближении (Zoom In) свечи трансформируются в высокодетализированный профиль объёма.

### Элементы ячейки кластера

- **Цветовой фон (Heatmap дельты)**
  - Зелёный фон — преобладают рыночные покупки (Ask > Bid).
  - Красный фон — преобладают рыночные продажи (Bid > Ask).
  - Интенсивность цвета зависит от силы перевеса.
- **Гистограмма объёма (Volume Profile)** — полупрозрачная белая шкала (заливка ~30%) внутри ячейки, отражает долю объёма этого уровня относительно максимального объёма во всей свече. Образует визуальный «колокол» профиля.
- **Выделение VPOC** — ячейка с максимальным объёмом в свече (Volume Point of Control) обведена чёткой белой рамкой.
- **Текстовые данные `Bid × Ask`** — точное количество рыночных продаж (слева) и рыночных покупок (справа) на уровне. Текст всегда видим и зафиксирован в читаемом размере.
- **Подсветка имбалансов (Imbalances)**
  - Если **Bid ≥ 2 × Ask** — число Bid становится ярким, жирным и красным.
  - Если **Ask ≥ 2 × Bid** — число Ask становится ярким, жирным и зелёным.

## 5. Жёсткий алгоритм сканера (4 правила входа)

Сканер ищет сигналы только внутри зон, нарисованных пользователем. Чтобы свеча была помечена как сигнал **LONG** (появился зелёный маркер), она должна одновременно удовлетворять **4 строгим правилам**:

1. **Полярность закрытия (`> 50%`)** — свеча обязана закрыться в верхней половине своего диапазона:
   ```
   close > (high + low) / 2
   ```
2. **Положительная общая дельта** — суммарная дельта всей свечи (сумма всех кластеров) должна быть строго положительной:
   ```
   total_delta > 0
   ```
   Это подтверждает доминацию покупателей по рынку в рамках текущих 5 минут.
3. **Закрытие относительно VPOC** — цена закрытия должна находиться строго выше уровня максимального объёма этой свечи:
   ```
   close > vpoc_price
   ```
4. **Поглощение на экстремуме (Absorption)** — на самом нижнем ценовом уровне свечи (Low) дельта кластера должна быть отрицательной:
   ```
   delta_at_low < 0
   ```
   Это означает, что на лое толпа била по рынку продажами, но крупный лимитный покупатель впитал их все (поглощение) и не дал цене упасть, после чего перехватил инициативу.

### Сигнал SHORT — зеркальная картина

```
close < (high + low) / 2     // полярность
total_delta < 0              // общая дельта
close < vpoc_price           // ниже VPOC
delta_at_high > 0            // поглощение покупок на хае
```

## 6. Формат входящих данных (CSV / JSON)

Для корректной работы сервиса в него необходимо загрузить исторические данные, агрегированные до 5-минутных свечей с кластерной разбивкой. **HTF (15m) строится терминалом автоматически.**

### Обязательные поля

| Поле | Тип | Описание |
|---|---|---|
| `timestamp` | `number` | Unix-время в миллисекундах. |
| `open` | `number` | Цена открытия. |
| `high` | `number` | Максимум. |
| `low` | `number` | Минимум. |
| `close` | `number` | Цена закрытия. |
| `volume` | `number` | Общий объём свечи. |
| `delta` | `number` | Общая дельта свечи. |
| `vpoc_price` | `number` | Ценовой уровень максимального объёма. |
| `clusters` | `Cluster[]` | Массив объектов с разбивкой по ценовым уровням. |

### Объект `Cluster`

| Поле | Тип | Описание |
|---|---|---|
| `price` | `number` | Цена уровня. |
| `bid` | `number` | Объём ударов в Bid (рыночные продажи). |
| `ask` | `number` | Объём ударов в Ask (рыночные покупки). |
| `vol` | `number` | Общий объём уровня (`bid + ask`). |
| `delta` | `number` | Дельта уровня (`ask - bid`). |

> Полная формализованная схема для валидации — в [`docs/03-data-format.md`](./03-data-format.md).
