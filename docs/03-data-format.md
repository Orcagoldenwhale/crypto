# Формат данных: 5m свечи с кластерами Footprint

> Единый контракт между Python-pipeline (Этап 7) и фронтендом (Этапы 2–6).
> Изменения здесь обязательно отражаются и в `data/loader.ts` (Zod), и в `data-pipeline/src/smc_data/schema.py` (pydantic).

---

## 1. Высокоуровневое описание

Файл представляет собой массив **5-минутных свечей** одного инструмента. Внутри каждой свечи — массив **ценовых кластеров** с шагом `tick_size`.

- **Таймфрейм:** строго 5 минут. 15-минутный таймфрейм агрегируется фронтендом из 3×5m.
- **Формат файла:** **JSON** (предпочтительный) или **CSV** (с сериализованным массивом кластеров в одной из колонок).
- **Кодировка:** UTF-8.
- **Сортировка:** строго по возрастанию `timestamp`.
- **Полнота:** допускаются «дыры» в данных (период низкой ликвидности), но если 5-минутка существует — она ОБЯЗАНА быть полной.

## 2. Корневая структура (JSON)

```json
{
  "meta": {
    "symbol": "BTCUSDT",
    "exchange": "binance",
    "timeframe": "5m",
    "tick_size": 5,
    "from": "2026-04-25T00:00:00Z",
    "to": "2026-04-30T00:00:00Z",
    "candles_count": 1440,
    "generated_at": "2026-05-01T22:00:00Z",
    "source": "binance-vision-aggtrades",
    "version": 1
  },
  "candles": [ /* Candle5m[] */ ]
}
```

### Поля `meta`

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `symbol` | `string` | ✅ | Тикер в верхнем регистре. |
| `exchange` | `string` | ✅ | Биржа (`binance`). |
| `timeframe` | `"5m"` | ✅ | Зафиксировано на 5 минут. |
| `tick_size` | `number` | ✅ | Шаг ценовых уровней (для BTC обычно `5`). |
| `from`, `to` | `ISO 8601` | ✅ | Границы периода (UTC, `to` эксклюзивный). |
| `candles_count` | `number` | ✅ | Количество свечей в массиве (для быстрой проверки целостности). |
| `generated_at` | `ISO 8601` | ✅ | Когда файл сгенерирован. |
| `source` | `string` | ✅ | Откуда взяты сырые данные. |
| `version` | `number` | ✅ | Версия схемы. Текущая — `1`. |

## 3. Объект `Candle5m`

```ts
type Candle5m = {
  timestamp: number;        // Unix ms, начало 5-минутного окна
  open: number;
  high: number;
  low: number;
  close: number;
  volume: number;           // = sum(clusters[].vol)
  delta: number;            // = sum(clusters[].delta) = sum(ask) - sum(bid)
  vpoc_price: number;       // цена кластера с максимальным vol
  max_vol: number;          // = max(clusters[].vol), для нормализации гистограммы
  delta_at_low: number;     // дельта кластера на уровне low (для правила сканера)
  delta_at_high: number;    // дельта кластера на уровне high (для правила сканера)
  clusters: Cluster[];
};
```

### Инварианты

1. `timestamp % (5 * 60 * 1000) === 0` — выровнен на 5-минутную сетку UTC.
2. `low ≤ min(open, close) ≤ max(open, close) ≤ high`.
3. `volume === clusters.reduce((s, c) => s + c.vol, 0)` (с допуском ±1 на округление).
4. `delta === clusters.reduce((s, c) => s + c.delta, 0)`.
5. `vpoc_price` присутствует среди `clusters[].price`.
6. `max_vol === Math.max(...clusters.map(c => c.vol))`.
7. `delta_at_low` соответствует кластеру с `price === low`. Если такого кластера нет — `0`.
8. `delta_at_high` соответствует кластеру с `price === high`. Если такого кластера нет — `0`.
9. `clusters.length ≥ 1`. Уровни идут с шагом `tick_size`, без пропусков по сетке (если на уровне не было сделок — кластер всё равно создаётся с нулями).

## 4. Объект `Cluster`

```ts
type Cluster = {
  price: number;            // нижняя граница ценового бакета, выровнена на tick_size
  bid: number;              // объём агрессивных продаж (taker SELL)
  ask: number;              // объём агрессивных покупок (taker BUY)
  vol: number;              // = bid + ask
  delta: number;            // = ask - bid
};
```

### Инварианты

1. `price % tick_size === 0`.
2. `vol === bid + ask` (без допуска).
3. `delta === ask - bid` (без допуска).
4. `bid ≥ 0`, `ask ≥ 0`.

### Терминология

- **bid** — рыночные продажи: агрессор ударил в стакан в **bid**-сторону. То есть это **taker SELL**.
- **ask** — рыночные покупки: агрессор ударил в стакан в **ask**-сторону. То есть это **taker BUY**.
- **delta = ask − bid** — положительная = доминируют покупки.

> На Binance в исходных AggTrades поле `isBuyerMaker = true` означает, что инициатор сделки был продавец (taker SELL), и объём такой сделки идёт в **bid**.

## 5. CSV-вариант

CSV-файл с теми же полями. Колонка `clusters` сериализуется как **JSON-строка** (с экранированием).

| Колонка | Пример |
|---|---|
| `timestamp` | `1714521600000` |
| `open` | `64200.0` |
| `high` | `64280.0` |
| `low` | `64150.0` |
| `close` | `64265.0` |
| `volume` | `2415.7` |
| `delta` | `+312.4` |
| `vpoc_price` | `64210.0` |
| `max_vol` | `412.3` |
| `delta_at_low` | `-58.1` |
| `delta_at_high` | `+12.0` |
| `clusters` | `"[{""price"":64150,""bid"":48.2,""ask"":12.0,""vol"":60.2,""delta"":-36.2}, ...]"` |

> CSV — это «совместимость», основной формат — JSON.

## 7. Версионирование
