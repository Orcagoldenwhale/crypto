# Пошаговый план реализации SMC Footprint Backtester

> Источник: `План разработки.docx`. Текст переформатирован в Markdown без потери смысла.
> **Актуальный прогресс с чекбоксами — в корневом [`PLAN.md`](../PLAN.md).**

Этот документ описывает поэтапную архитектуру создания сервиса. Каждый этап должен завершаться тестированием перед переходом к следующему.

---

## ЭТАП 1: Добыча и подготовка данных (Data Pipeline)

Браузеру тяжело переваривать сырые тики. Задача этого этапа — написать Python-скрипт, который скачивает сырые сделки и превращает их в лёгкий CSV-файл готовых кластеров для фронтенда.

### Шаг 1.1: Где взять сырые данные?

- **Вариант А (бесплатный, выбран)** — сайт `data.binance.vision` → Data → Spot → Monthly или Daily AggTrades. Скачиваем zip-архивы с CSV файлами тиков по нужной паре (например, `BTCUSDT`).
- **Вариант Б (платный, но удобный)** — API Tardis.dev. Позволяет выкачивать готовые трейды строками кода.

### Шаг 1.2: Скрипт-агрегатор (Python / Pandas)

Пишем локальный скрипт, который «читает» миллионы тиков из скачанного файла и группирует их:

1. Группируем время по 5 минут (таймфрейм LTF).
2. Внутри каждых 5 минут группируем тики по шагу цены (например, $5 или $10 для BTC).
3. Считаем для каждого уровня: `bid_volume` (удары по рынку в селл), `ask_volume` (удары по рынку в бай).
4. Высчитываем OHLC, общую дельту, общий объём и находим цену VPOC.

### Шаг 1.3: Экспорт в нужный формат

Скрипт сохраняет результат в файл `processed_data.json` или CSV.

**Проверка этапа:** открываешь итоговый файл. В нём должно быть около 288 строк на 1 день торгов (5-минутки). Внутри каждой строки должен быть массив ценовых уровней с бидами и асками.

## ЭТАП 2: Базовый UI и рендер свечей (Frontend Foundation)

Создаём «каркас» приложения и учимся просто рисовать классический график.

### Шаг 2.1: Вёрстка макета

Используя React и Tailwind CSS, создаём Fullscreen-макет: верхняя полоска (Header), плавающее меню слева (Toolbox) и пустой чёрный квадрат под график.

### Шаг 2.2: Рендер классических свечей

1. Пишем загрузчик: приложение читает наш JSON/CSV из Этапа 1.
2. Пишем движок отрисовки: берём координаты цены/времени и переводим их в координаты экрана (пиксели). Рисуем обычные зелёные и красные палочки (свечи).

**Проверка этапа:** на экране виден статичный 5-минутный свечной график загруженного дня.

---

## ЭТАП 3: Интерактивность и HTF Контекст

Оживляем график и добавляем возможность разметки.

### Шаг 3.1: Навигация (Pan & Zoom)

Привязываем события мыши `onWheel` (колесико), `onMouseDown` и `onMouseMove`. Пересчитываем видимую область графика при их изменении.

**Проверка этапа:** график можно плавно двигать влево-вправо и масштабировать, он не должен «улетать» за экран.

### Шаг 3.2: Агрегация HTF (15m)

Пишем функцию внутри React, которая берёт массив 5-минуток и склеивает каждые 3 свечи в одну 15-минутную. Добавляем кнопку переключения экранов (15m ↔ 5m).

### Шаг 3.3: Рисование POI зон

Добавляем инструмент «Прямоугольник». Клик → тянем → отпускаем. Сохраняем координаты углов прямоугольника (Цена от/до, Время от/до) в массив `poiZones`.

**Проверка этапа:** зоны рисуются, сохраняются, не исчезают при сдвиге графика и корректно масштабируются.

---

## ЭТАП 4: Микроструктура и Кластера (Footprint)

Самая визуально сложная часть — отрисовка внутренностей свечи.

### Шаг 4.1: Детальный рендер кластеров

1. Настраиваем условие: если включён 5m таймфрейм и ширина свечи на экране больше X пикселей → переключаем режим рендера.
2. Вместо свечи рисуем столбцы (гистограмма объёма) и текст `Bid × Ask` из данных, полученных на Этапе 1. Подсвечиваем VPOC белой рамкой.

**Проверка этапа:** при сильном приближении (Zoom In) свечи «раскрываются» в кластера. Текст не слипается, дисбалансы светятся яркими цветами.

### Шаг 4.2: Бесшовный переход (Zoom-in по клику)

Привязываем клик по нарисованной зоне на 15m графике: меняем таймфрейм на 5m и устанавливаем видимые границы времени ровно по границам этой зоны (+ небольшие отступы по краям).

---

## ЭТАП 5: Алгоритм-сканер (Бизнес-логика)

Пишем ядро стратегии — те самые 4 правила для нахождения идеального входа.

### Шаг 5.1: Функция проверки сетапа

Создаём изолированную функцию `checkSignal(candle_data)`, которая возвращает `LONG`, `SHORT` или `null`.

```ts
close > (high + low) / 2     // Полярность
delta > 0                    // Общая дельта
close > vpoc_price           // Уход от объёма
delta_на_самом_лоу < 0       // Поглощение рыночных продаж
```

### Шаг 5.2: Интеграция с UI

По нажатию «ПОИСК ВХОДОВ» фильтруем только те 5m свечи, которые попали в координаты нарисованных зон POI. Прогоняем их через `checkSignal`. Если найдено — красим зону в зелёный и ставим маркер под свечой.

**Проверка этапа (ФИНАЛ MVP):** загружаем реальный день торгов. Размечаем зону. Жмём поиск. При клике на зону нас кидает в 5m, и мы глазами видим, что свеча, над которой стоит зелёный маркер, ИДЕАЛЬНО соответствует всем 4 правилам на футпринте.

## ЭТАП 6: Оптимизация (Performance Guide)

Текущий прототип работает на SVG. Это нормально для тестов на 300 свечах. Но для реальной истории (месяцы торгов) SVG заставит браузер зависнуть. Как сделать сервис быстрым:

### Переход на `<canvas>` (обязательно для продакшена)

Вместо рендера тысяч DOM-элементов `<rect>` и `<text>` использовать нативный Canvas API (`ctx.fillRect`, `ctx.fillText`) или библиотеки вроде PixiJS / Lightweight Charts (с кастомными плагинами для кластеров). Canvas переваривает 100 000+ элементов при 60 FPS.

> В нашей реализации мы идём на Canvas **с самого начала** (Этап 3 в `PLAN.md`).

### Web Workers (для сканера)

Если сканировать полгода истории, цикл поиска может заморозить интерфейс (кнопка залипнет на пару секунд). Вынести функцию `runScanner` в отдельный поток через Web Worker.

### Виртуализация данных (Windowing)

Не передавать в функцию рендера весь массив данных. Использовать `visibleData = data.filter(...)`, чтобы браузер «знал» и отрисовывал только те свечи, которые сейчас физически помещаются в ширину экрана.

### Хранение в IndexedDB

Если загружать большие CSV/JSON файлы каждый раз — это долго. После первого парсинга файла сохранять распарсенный массив в базу данных браузера (IndexedDB). Следующий запуск будет происходить за миллисекунды.

## Краткий гайд для пользователя

Как работать с готовым сервисом:

1. Скачайте CSV/JSON-файл истории (уже прогнанный через Python-агрегатор) с вашего компьютера.
2. Нажмите «Загрузить историю» в правом верхнем углу терминала.
3. На экране HTF 15m оцените контекст рынка (нисходящие/восходящие тренды, сломы структуры).
4. В левом меню включите инструмент «Разметка» (иконка руки).
5. Зажмите левую кнопку мыши и растяните прямоугольники (POI) над зонами ордер-блоков или имбалансов, куда ожидаете возврат цены.
6. Нажмите зелёную кнопку «ПОИСК ВХОДОВ».
7. Если внутри какой-либо зоны алгоритм обнаружил поглощение, смещение VPOC и правильную дельту — эта зона окрасится в ярко-зелёный цвет.
8. Переключите инструмент мыши обратно на «Навигацию».
9. Кликните по зелёной зоне и нажмите «Перейти на LTF».
10. График автоматически увеличит нужный участок. Проанализируйте сформированный кластер визуально, проверьте уровни Бидов и Асков, чтобы принять финальное решение о качестве этого бэктест-входа.
